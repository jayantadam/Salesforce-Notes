Connected App Inbound (External system calls Salesforce)
    External Client App Manager
        External Client App Manager is a feature in Salesforce that allows you to manage and monitor connected apps that are used for external integrations.
        It provides a centralized interface to view and control the connected apps, their usage, and their access to Salesforce data.
        You can use the External Client App Manager to:

old way setup -> connected apps -> create connected app
new way setup -> external client app manager -> create external client app

create user with appropriate permissions to access the connected app and API endpoints.
    you should create a dedicated integration user in Salesforce with the necessary permissions to access the connected app and API endpoints. 
    This user will be used for authentication when the external system calls Salesforce APIs.

    1. User License -> Salesforce Integration and Profile-> Salesforce API Only System Integrations
                    OR
    2. permission set -> system permissions -> API Enabled and API Only User -> assign to the integration user

before creating a connected app, we need to understand the types of apex integration in salesforce. 
USE of API Integration User - API integration user is a dedicated user in Salesforce that is used for authentication and access when external systems call Salesforce
APIs. This user is typically assigned specific permissions and profiles to ensure secure and controlled access to Salesforce data and functionality. 
The API integration user is essential for maintaining security and managing access when integrating external systems with Salesforce.

 🔒 Example:
    API needs to read Accounts → give only Read on Account
    No need for full admin rights

1. create integration user in salesforce with appropriate permissions to access the connected app and API endpoints.
2. create api user permissions set and assign it to the integration user.
    steps to api user permissions set:
    1. Go to Setup → Permission Sets → New Permission Set
    2. Enter Label (e.g., API User) and API Name (e.g., API_User) → Save
    3. In the permission set, go to "System Permissions" → Edit → Enable "API Enabled" → Save
        i) API Enabled	- Access any Salesforce.com API.
        ii)API Only User - Access Salesforce.com only through a Salesforce.com API.
    4. Assign the permission set to the integration user.

3. Create Connected App with OAuth 2.0 with client credentials flow in Salesforce
    Setup → App Manager → New Connected App/External Client App Manager
    i) Fill Basic Information:
        * Name: External System Integration
        * API Name: External_System_Integration
        * EMail: example@company.com
    ii) API (Enable OAuth Settings):
        * Enable OAuth Settings
        * Set Callback URL (e.g., https://www.getpostman.com/oauth2/callback) 
            //why we need callback url for external system? -> because after successful authentication, Salesforce will redirect to this URL with the access token 
            in the response. This allows the external system to receive the access token and use it for subsequent API calls to Salesforce.
            example: if you are using Postman to test the API, you can set the callback URL to https://www.getpostman.com/oauth2/callback which is provided by Postman 
            for testing purposes. After you click "Request Token" in Postman, it will handle the OAuth flow and receive the access token in the callback URL.
        * Select OAuth Scopes - Selected OAuth Scopes
                                    Full access (full)
                                    Manage user data via APIs (api)
                                    Perform requests at any time (refresh_token, offline_access)
                                    Manage user data via Web browsers (web)
    iii) Flow Enablement
        *Enable Client Credentials Flow (if using client credentials flow)        
    iv) create connected app and wait for it to be active (can take up to 10 minutes)
    v) set oauth policies (optional) -  
        *mandatory STEP - go to OAuth Flows and External Client App Enhancements - add username and set "Run As" user for client credentials flow
        (this user will be used to authenticate and access Salesforce APIs when external system calls Salesforce using client credentials flow)
        *Permitted Users - set to "Admin approved users are pre-authorized" / allows users
       *set profile or permission set to allow access to the connected app
       *set token expiration, refresh token policies, etc.
       
    * Save it
    GO TO SETTING -> oauth settings -> find your connected app -> click on it -> manage consumer details -> note down client id and client secret for authentication.

4. Get Access Token from External System Use OAuth 2.0 flow  to get access token using Client ID and Secret.
   Get your domain name from Setup-> My Domain -> Current My Domain URL (e.g., https://yourInstance.salesforce.com)
   Use the access token obtained from the previous step to call Salesforce API endpoints from the external system

    Open postman -> create new request -> set method to POST -> enter URL (https://yourInstance.salesforce.com/services/oauth2/token)
      -> Go to Body tab -> select x-www-form-urlencoded -> enter parameters (grant_type, client_id, client_secret)
       -> password should be in the format: password + security token if password flow is used (e.g., mypassword + 123456)
       -> grant_type should be "password" for password flow or "client_credentials" for client credentials flow
       -> click Send -> check response for access token and instance URL.

5. Make API Call to Salesforce
        url: https://yourInstance.salesforce.com/services/data/v59.0/sobjects/Lead/
        method: POST
        headers: Authorization: Bearer your_access_token
        body: JSON data for Lead (e.g., {"LastName":"Ravi","Company":"ABC Company","Phone":"9876543210"})
     Use access token in Authorization header to call Salesforce REST API endpoints.

6. You can also create **Custom Apex REST API** for complex logic or custom endpoints. Create an Apex class with @RestResource annotation and define methods with
 @HttpGet, @HttpPost, etc. to handle requests.

7. For inbound calls, ensure proper authentication and permissions are set up for the connected app and API access.

8. You can also use **Named Credentials** to manage external endpoints and authentication securely without hardcoding URLs and credentials in Apex code.
    Example of using Named Credential in Apex:
        HttpRequest req = new HttpRequest();
        Http http = new Http();
        req.setEndpoint('callout:My_Named_Credential/account');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setBody('{"name":"Test Account"}');
        HttpResponse res = http.send(req);

connected app disadvantages:
    1. Complexity - setting up a connected app with OAuth can be complex and requires understanding of OAuth flows, token management, and security considerations.
    2. Maintenance - managing connected apps and their credentials can require ongoing maintenance, especially if there are multiple external systems integrating with Salesforce.
    3. Performance - if not implemented correctly, using connected apps for integration can lead to performance issues due to token expiration, refresh token handling, and API limits.
    4. Security Risks - if the connected app is not configured securely (e.g., weak client secret, improper permissions), it can pose security risks to the Salesforce org.
    5. User Experience - for user-based OAuth flows, users may need to authenticate and grant permissions, which can impact the user experience if not handled smoothly.

  External client app advatages:
1. packageble metadatabased construct - an external client app packageble to be installed in multiple orgs without the need for manual configuration of connected 
                                        apps in each org.
2. security - improved  securiry, supports disctinct profile and permission and admin role to set for better access control, and provides a more secure way to manage
              external integrations.    
3. support 2nd genration packaging (2Gp)- allows source driven development in scratch orgs and makes mirgration and management of integarion user, easy deployment to multiple orgs, making it ideal for ISVs and enterprise customers with complex integration needs. 
2. centralized interface to manage and monitor - it provides a centralized interface to manage and monitor connected apps across multiple orgs, making it easier to track usage and access.
3. security and access control - it allows for better security and access control by providing a single point of management for connected apps and their permissions.
4. 2gb data storage - it provides a dedicated storage for connected app data, allowing for better organization and management of app-related information.
