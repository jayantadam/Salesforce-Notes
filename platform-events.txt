## Scenario

“When an Opportunity is marked **Closed Won**, publish a Platform Event.  
A subscriber (Apex Trigger on the event) creates a follow‑up Task for the Opportunity Owner.”

***

## 1) Define the Platform Event

Setup → **Platform Events** → New

*   **Label**: Opportunity Won Event
*   **API Name**: Opportunity\_Won\_Event\_\_e
*   **Fields** (example):
    *   OpportunityId\_\_c (Text, 18)
    *   Amount\_\_c (Number, 18,2)
    *   OwnerId\_\_c (Text, 18)
    *   Message\_\_c (Text, 255)

> After saving, **Deploy** the event (if org requires).

***

## 2) Publisher (Apex) – Fire event when Opp becomes Closed Won

Create an **after update** trigger on Opportunity:

```apex
trigger OpportunityAfterUpdate on Opportunity (after update) {
    List<Opportunity_Won_Event__e> eventsToPublish = new List<Opportunity_Won_Event__e>();

    for (Opportunity newOpp : Trigger.new) {
        Opportunity oldOpp = Trigger.oldMap.get(newOpp.Id);

        // Publish only when Stage changes to Closed Won
        if (newOpp.StageName == 'Closed Won' && oldOpp.StageName != 'Closed Won') {
            eventsToPublish.add(new Opportunity_Won_Event__e(
                OpportunityId__c = newOpp.Id,
                Amount__c       = newOpp.Amount,
                OwnerId__c      = newOpp.OwnerId,
                Message__c      = 'Opportunity Closed Won'
            ));
        }
    }

    if (!eventsToPublish.isEmpty()) {
        Database.SaveResult sr = EventBus.publish(eventsToPublish);
        // Optional: check sr.isSuccess() or sr.getErrors() for logging
    }
}
```

> You can also publish from **Flow** (Record-Triggered Flow on Opportunity → Action: **Publish Platform Event**) using the same fields.

***

## 3) Subscriber (Apex) – Listen to the event and create a Task

Create an **Apex Trigger on the Platform Event**:

```apex
trigger OpportunityWonEventTrigger on Opportunity_Won_Event__e (after insert) {
    List<Task> tasks = new List<Task>();

    for (Opportunity_Won_Event__e evt : Trigger.new) {
        if (String.isBlank(evt.OpportunityId__c) || String.isBlank(evt.OwnerId__c)) continue;

        tasks.add(new Task(
            WhatId      = Id.valueOf(evt.OpportunityId__c),
            OwnerId     = Id.valueOf(evt.OwnerId__c),
            Subject     = 'Follow up after Closed Won',
            Priority    = 'High',
            Status      = 'Not Started',
            Description = evt.Message__c + ' | Amount: ' + String.valueOf(evt.Amount__c)
        ));
    }

    if (!tasks.isEmpty()) {
        insert tasks;
    }
}
```

This trigger runs asynchronously when events arrive, and creates Tasks accordingly.

## (Optional) Subscribe from LWC (Realtime UI)

If you want the UI to react instantly, use `empApi` to subscribe to the event channel.

**LWC JavaScript (opportunityWonListener.js):**

```javascript
import { LightningElement } from 'lwc';
import { createMessageContext, releaseMessageContext, subscribe, unsubscribe } from 'lightning/messageService';
import EMP_API from 'lightning/empApi';

export default class OpportunityWonListener extends LightningElement {
    channelName = '/event/Opportunity_Won_Event__e';
    subscription = {};
    context = createMessageContext();

    connectedCallback() {
        this.handleSubscribe();
    }

    disconnectedCallback() {
        this.handleUnsubscribe();
        releaseMessageContext(this.context);
    }

    handleSubscribe() {
        const messageCallback = (response) => {
            const payload = response?.data?.payload;
            // Do something with payload fields, e.g. show a toast
            console.log('Event Received:', payload);
        };
        EMP_API.subscribe(this.channelName, -1, messageCallback).then(response => {
            this.subscription = response;
        });
    }

    handleUnsubscribe() {
        if (this.subscription && this.subscription.id) {
            EMP_API.unsubscribe(this.subscription, () => { this.subscription = null; });
        }
    }
}
```

> Note: In newer implementations, use the **empApi** or **CometD** pattern supported by Salesforce. Ensure the component has the right permissions (Lightning page, user profile).

***

## Key Notes (Quick)

*   **Transaction**: Publishing is part of the same transaction as your trigger/Flow. Event delivery is async and **eventual**.
*   **Ordering**: Events are ordered **per transaction**, not globally.
*   **Limits**: Check Platform Event publish limits (per hour/org) and event payload size.
*   **Security**: Subscribers run in **system context** (event triggers), so handle validation and guardrails.
*   **Replay**: Streaming API supports **replayId** to resume from a point in time (UI/CometD subscribers).
*   **Error handling**: If subscriber fails, it retries according to the event bus policies (but design idempotent logic).
